## 1. Strongest findings — MUST be enforced as hard gates

**M1 + M2 + M3 + M5 are the build-killers.** All four are mechanically probeable today, which means leaving any of them unresolved converts a deterministic failure into a future silent drift event. Enforce in this order:

1. **M1 (schema target) — CRITICAL, enforce as `G-SCHEMA-1`.** Three independent reviewers found the same wrong filename (`evidence-item.v1` vs `$defs.atom` in `bayesian-update.v1`/`decision-analysis.v1`). A plan that cites a schema the output cannot satisfy is not an ambiguity, it is a guaranteed spec-drift event with no interceptor. The cross-check (grep artifact specs for schema filenames → assert each filename validates a committed engine-output fixture) is cheap, binary, and catches every future instance of the same failure class. The `input_trust_class` extension to the provenance enum is *deferred to Carlini's lens* — evaluation enforces whatever enum the security reviewer defines, but I support it: it is a schema field, i.e., an architectural control, not prompt wording.
2. **M2 (Green-then-Red + self-grading) — CRITICAL, enforce as `G-TDD-1` + `G-TAMPER-1`.** Four reviewers converged. The plan's dependency line ("tests depend on their respective calculation modules") is documentation of a process that manufactures the failure class it claims to prevent. The packet adds the sharper point: `tests/mutation/` already exists and the plan ignores it. Mutation testing is the *only* defense against the same-agent-writes-both self-grading problem — a test suite that survives killing the implementation is a tautology suite. Gate: every new test file must be mutation-verified (≥1 mutant killed per test class), and the RED artifact (pre-implementation failing run log) must be committed before the module lands.
3. **M3 (seed=None + lying signatures) — CRITICAL, enforce as `G-DET-1/2`.** The packet's D-finding upgrades mine: deterministic functions accepting a `seed` no RNG consumes is a *deception in the public API* — it makes callers believe determinism was purchased when nothing was varied. Worse, a hostile seed (string, bool) "silently changes semantics" and flows into `canonical_hash`. My AST-lint gate extends cleanly: `seed` parameter must be typed `int` (reject `Optional[int]`), must be consumed by an RNG *or absent entirely* — never present-but-dead. `simulation.py` already implements the correct pattern (`isinstance(seed, int) and not isinstance(seed, bool)`); the gate is "diff every new signature against the existing precedent."
4. **M5 (no computation site for the ensemble) — CRITICAL, enforce as `G-COMPILER-1` + `G-RECEIPT-1`.** Three reviewers, including this one, identified the same structural veto: the flagship feature currently has no computation site, so by default it *is* the direct LLM→final-artifact pipeline. There is no version of "the LLM judges robust conclusions" that survives my non-negotiable #9. The compiler-over-IR architecture from Round 1 (A1) stands unchanged, with the robustness threshold as a human-owned named constant and a golden-file drift test.
5. **M8 (validation as prose) — HIGH, enforce as `G-VALID-1`.** "Control-by-doc is prompt-security" is exactly right, and the packet supplies the concrete precedent the gate needs: `simulation.py`'s rejection pattern (isfinite, bool exclusion, `unavailable_result` fallback) already exists. The gate becomes trivially mechanical: a conformance test imports each of the 8 new modules, feeds each the standard adversarial input battery, and asserts the `unavailable_result` shape — no traceback reaches output, `reason` names the violated invariant. Resource caps (NK n, matrix size, grid, days, horizon) become named shared constants with a unit test per ceiling. Copy the existing convention; do not invent one.
6. **M9 (grounding contradictions) — HIGH, enforce as `G-PAGE-1` per Page condition.** Cyclic/reducible chains silently fabricating a stationary distribution is not a numerical nuance — it is the engine asserting a mathematical falsehood with provenance `calculated`. Four adversarial fixtures (one per failed Page condition) + SIR negative-state test + Polya multi-trial signature correction. The plan's Euler-vs-difference-equations contradiction must be resolved *by reference to the grounding doc*, and the grounding doc's computable claims (per E's finding) become golden fixtures — which kills two findings with one mechanism.
7. **M7 (no adversarial fixtures) — HIGH.** `fixtures/adversarial/` exists with 10 fixtures; the plan adds zero. Gate: every new module has ≥1 adversarial fixture per documented failure mode, committed before the module's tests go green. This is the same mechanism as `G-UNAVAIL-1` from Round 1, generalized.
8. **M6 (Committee Mode six-string vocabulary) — HIGH.** The packet's discovery that `runner.py` silently degrades novel recommendation strings to `recommendations[0]` converts my Round 1 "spec hole" into a *latent silent-failure*. dlc-page cannot start Phase 3 until the disagreement contract is schema-defined against `committee-result.v1` and a probe renders two committed outputs and diffs them mechanically. If the vocabulary is the constraint, it must be validated at the boundary, not defaulted silently.

## 2. Wrong or over-weighted findings

**M10 (scope/outcome) — over-weighted as stated, but with one correct kernel.** F's "no named customer outcome" and "2-4-10 absent" are product-lens objections; per my card I do not own product decisions and will not gate on vibes-adjacent criteria like "moment of value." However, two of F's points are mechanically enforceable and I adopt them: (a) *nothing consumes `ensemble-result.v1`* — an artifact with no consumer is unverifiable in e2e terms, so the gate is: at least one committed test path feeds a real ensemble result into `decision-analysis` and asserts the verdict changes or explicitly documents why it does not; (b) *byte-exact cache-prefix threat from 8 reference files + SKILL.md + DLC* — this is a token-budget problem, enforceable as `G-TOKEN-1` (line/byte budgets per file, measured against the repo's largest existing SKILL.md). The "cut to ≤4 models" recommendation itself: that is a product judgment; the harness gate is only that the count is a named constant, not hardcoded prose in a router. AI-Tourism veto on SIR/Bass/Blotto/NK — governor's call, not mine.

**M11 (determinism undefined) — correct finding, partially over-weighted.** Bit-exact vs tolerance *is* a real spec hole, but requiring bit-exact float determinism across arbitrary CPython versions is not achievable for every model (transcendental functions vary by libm). The binary resolution: pin the interpreter version in CI (a lockfile check, trivially mechanical), define canonical JSON float serialization once in a shared serializer (the repo already has `canonical_sha256` — extend it), and byte-compare replays *within that pinned environment*. Anything outside the pin is out of scope, stated as such. Do not attempt cross-version bit-exactness; it is a non-converging gate.

**M4 (fake open questions) — correct, but B's sub-finding is the sharper half.** My Round 1 gate `G-SPEC-1` stands; the packet's addition that Artifact 17 hard-codes a nonexistent subcommand (`capital model-thinking run`) is a *concrete hallucination already committed into the spec* — that single line proves the whole failure class. Enforce: the probe job must not merely diff the open-questions table, it must validate every CLI invocation string in the plan against the parsed command registry in `plugin/commands.py`. Any invocation string not in the registry = gate fails.

**E's "grounding doc is an LLM transcript cited as authority" — over-weighted as an objection to the plan, correctly weighted as a testing requirement.** I do not evaluate the epistemic pedigree of source documents (not my lens). But it doesn't matter whether the grounding doc is authoritative: its *computable* claims (75/25 equilibrium, Diversity Prediction Theorem, V≥1−1/R0) are testable, so under my rules they become golden fixtures regardless of provenance. If the grounding is wrong, the golden fixture fails and the human resolves the contradiction — the harness surfaces the disagreement mechanically. That is the correct disposition, not a veto.

**C's injection loop — real, but the primary fix belongs to Carlini's lens.** The untrusted-evidence→numeric-parameters path is a threat-model problem; what I own is the enforcement: (a) `input_trust_class` in the provenance enum (schema-level, adopted from M1), (b) the free-text `condition`/`point_of_contention` echo channel into Committee Mode must be either length-capped and schema-validated or removed — unbounded free text flowing back into agent context is an architectural hole regardless of intent, and "unbounded" fails a binary check. I defer to C on *what* the trust rules are; the gate above is how they become enforceable.
