## Round 2 — Judging the Merged Findings

### 1. Strongest — MUST be enforced as gates

- **M2 (Green-then-Red, no eval-tamper defense).** Strongest finding in the packet. Every artifact orders tests AFTER the module, and the same agent grades its own work. My Round 1 W-R4/W-R5 said exactly this. "All tests pass" from the implementing agent is an unattested claim. Gate must require: recorded red-run evidence per module in the build ledger + one mutation spot-check per phase (flip a constant in markov.py/sir.py, suite must go red). Enforce fully.
- **M5 (no computation site for ensemble aggregation).** This is the flagship feature and today it is an LLM→final-artifact pipeline — the exact violation of the structured-output compiler pattern (Rule 9). "Robust conclusions" judged freehand means canonical_hash is provenance theater. Enforce as a Phase 1 blocker: a deterministic `ensemble.py` compiler over a typed Ensemble IR, with round-trip tests. This is also the highest-severity *security-adjacent* finding: the compiler is the choke point where trust-class gating can be enforced mechanically (see M1/C).
- **M7 (zero adversarial fixtures) + M8 (validation-as-prose).** Same root cause: the plan tests only the average case and enforces input bounds in documentation. Control-by-doc is prompt-security. Enforce as one combined gate: 8/8 models carry ≥1 adversarial fixture under `fixtures/adversarial/`, and every "validates input" AC is a test that physically fails (typed rejection + `unavailable_result`), matching the existing `simulation.py` rejection pattern.
- **M1 (wrong schema target + missing trust dimension).** Enforcing conformance against `evidence-item.v1` is checking the wrong artifact — the conformance gate would pass atoms that violate the real contract. And without `input_trust_class`, injected evidence is indistinguishable from filings downstream. Enforce: conformance re-targeted to `$defs.atom` in `bayesian-update.v1`/`decision-analysis.v1`, schema re-validated, and `input_trust_class` added with a round-trip test.
- **M4 (fake open questions).** "Open questions" that are answerable by one repo probe are not open — they force the implementing agent to hallucinate interfaces (Artifact 17 hard-codes a subcommand that does not exist). Enforce as a Phase 0 grounding audit: Kelly at `allocation.py:41`, registry at `plugin/commands.py`, packs dict in `methods/packs.py`, real invocation `capital method run --pack` — recorded in the plan before any skill authoring. Cheap, mechanical, prevents an entire class of fabrication.
- **M9 (spec contradicts its own grounding doc).** Markov power-iteration-only vs the four Page convergence conditions; SIR Euler vs discrete difference equations (goes negative, violates conservation); Polya single-trial vs multi-trial-spread; bandit algorithm names that don't match grounding. A plan that contradicts its grounding doc has no grounding. Enforce per model: detector for non-ergodic/cyclic/absorbing chains with `unavailable` output (tested); SIR reformulated to the grounded difference equations with a conservation test; Polya signature re-specced; bandit algorithms reconciled to grounding.
- **M6 (Committee Mode mechanics undefined but used as a Phase 3 gate).** An unmechanized claim in an acceptance gate is ungateable — and `runner.py`'s fixed six-string vocabulary silently degrades novel dlc-page strings to `recommendations[0]`. Enforce: mechanism (function name + comparison fields) documented in Phase 0, before Artifact 22 design; vocabulary extension or mapping table tested.
- **C's injection loop + D's machine-readable α≤2 veto (single-reviewer, but must not be averaged away).** These are the two findings closest to my Round 1 operating question. The α≤2 router rule gating real money MUST be schema/engine-enforced, not skill prose (my W-R3). And the untrusted-evidence→numeric-parameter path needs a provenance_class whitelist for what may populate engine parameters. Enforce both as Phase 1 engine gates.

### 2. Wrong or over-weighted

- **M10 scope critique (partially over-weighted by F, endorsed by me only in its cache/context half).** F's "no named customer outcome / 2-4-10 violation" is real but it is a product lens, not a build blocker for a Phase 1 calculation library. What I keep from M10 is the machine-checkable half: token budget + cache-prefix measurement (W-G8), and a cap on decision-relevant models. What I do not gate: writing a customer-outcome document is not a binary mechanical check and does not block code. Route it to the human governor as a scope decision, not a gate. F's strongest concrete point — the 2-4-10 escalation absent — stands as a Phase 4 smoke-test gate (run one real thesis through extract→ensemble→decision hook once), which IS binary.
- **M3 severity, partially.** A/C/D's `seed=None` finding is correct on the convention violation (C4 untestable), and D's "deterministic functions accept a seed no RNG consumes" is a genuine signature lie. But "hostile/typed seeds silently change semantics" is over-weighted: seed validation is one line (`isinstance(seed, int)` rejection), not an architecture problem. Enforce the signature hygiene (seed only where RNG exists, type-checked) as a small test, not a phase blocker.
- **M11 determinism policy, partially.** Bit-exact vs tolerance policy and CPython pinning are real, but for a stdlib-only, pure-combinatorics suite most outputs are exact integers/rationals; tolerance policy is only needed for SIR/Euler-style continuous paths. Enforce a narrow gate: CPython version pinned in ledger, and every test that compares floats declares exact-or-tolerance explicitly. Do not gate a full numerical-audit regime.

### 3. Still missing (nobody in the packet said it)

- **Egress proof.** No reviewer demanded a test that `calculations/` performs zero network I/O and that a model-thinking run makes no outbound connections. This is my W-G1 and it directly answers my operating question; it is ~20 lines and fully binary. Add it.
- **Injection refusal end-to-end test.** C described the loop anatomically but nobody specced the test that closes it: feed attacker-controlled evidence text through extract→ensemble, assert (a) injected instructions never reach privileged computation, (b) the atom is recorded unverified, (c) run output is byte-identical with and without the injection. This is THE test for the operating question. Add it.
- **Free-text fields as injection echo.** C flagged condition/point_of_contention as unbounded echo channels; nobody converted it to a gate. Fix: length/type caps at schema level + the compiler rejects free text outside a declared charset/length. Binary.
- **Grounding-claims verification.** (My W-R8, survived into packet as E-only, under-weighted.) The grounding doc is an LLM transcript cited as authority. Computable claims (75/25 equilibrium, Diversity Prediction identity, V ≥ 1−1/R0) are one-line tests; "5–7 sweet spot" enters router guidance with no primary source. Add `test_grounding_claims.py` + citation requirement for non-computable claims.
- **Aspirational ACs.** M11 half-flagged it; my W-R10 handles it: "useful/clear/accurate" criteria are vibes and must be replaced with binary checks or dropped.

### 4. Human-governor decisions

1. **Q-W1 carried forward (trifecta ruling).** Governor must pick: (a) privacy-layer extension artifact, or (b) declare the existing ingest/extract/confirm quarantine authoritative and accept residual risk in writing. "Both later" is not an answer. This is the only decision that can block Phase 2.
2. **Q-W4 (test-first vs compensating verification).** Hold the agent to recorded red runs (strict), or accept test-after with independent re-run + mutation check (compensating)? Pick one; the plan currently does neither.
3. **Q-W5 (context ceiling).** A number for added loaded-context tokens per representative run, without which the cache-prefix gate (W-G8) cannot pass/fail.
4. **Q-W6 (sweet-spot claim).** Ship "5–7 models" with citation flag, or require primary-source (Miller & Page) verification before it enters skill prose.
5. **Q-W7 (friction waiver, self-check).** My known failure mode is security friction killing velocity. If the governor judges blast radius small (local-only personal finance tool), they may waive named gates — in writing. A recorded waiver is legitimate; silent skipping is the normalization of deviance I warn against.
6. **From M10/F (scope):** does ensemble output get wired to a decision hook in this phase, or shipped as analysis-only? If analysis-only, the decision-hook gate becomes a documented deferral, not a silence.
