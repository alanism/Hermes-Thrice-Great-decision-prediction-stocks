# Round 2 Adversarial Review — [N] Nicholas Carlini (Reviewer C)

**Operating question:** "If an attacker controls one external input to this system, can they hijack the agent's control flow?"

**Stance carried forward from Round 1:** this is a local research tool behind a human authorization gate, so per my cost-to-attack release valve I still do *not* demand sandboxing, egress controls, or red-team CTF infrastructure. What I demand is that the deterministic engine hard-fail structurally on hostile inputs, and that no safety property lives in a prompt sentence. My Round 1 gates G1–G8 are on the table; below I judge the merged packet, then issue the final register.

---

## 1. Strongest findings — MUST be enforced as binary gates

**M5 (ensemble aggregation has no computation site) — strongest in the packet.** I flagged this blind as R5 and B and A independently converged. It is the flagship feature of the plan, and as written the "never compute freehand" rule is violated by the feature itself: `robust_conclusions` computed by the LLM is attacker-influencable through any single model's parameters, and `canonical_hash` over LLM-judged output is provenance theater. My gate G4 stands: a deterministic `aggregate()` with unit tests and `aggregated_by: "engine"` in the schema, or the build does not pass Phase 2.

**M7 + M8 (all-valid fixtures; validation is prose) — the cheap, decisive pair.** I flagged both blind (R7, R1/R2). Merging them changes nothing about enforcement: the repo already has the `fixtures/adversarial/` convention and the `simulation.py` rejection pattern, so the plan is *declining to inherit existing, tested architecture* — that is a scope decision, not an unknown. Every "validates input" AC and every doc-only size cap ("kept small in documentation") is a prompt standing where a test belongs. Gates G1, G2, G6.

**M1 (wrong schema target + `input_trust_class`).** My blind finding converged with A and E. The `evidence-item.v1` mismatch means the conformance gate as written validates the wrong artifact shape. The proposed `input_trust_class` field is *my* R4 gate restated in schema terms — provenance must be machine-readable data the engine branches on, not a skill-prompt instruction. Gate G8 (reject untrusted provenance classes as model parameters, stable reason code).

**M3 (seed contract broken).** Converged across A/C/D. `seed=None` makes C4 ("every number reproducible from inputs+seed") untestable — the acceptance criterion is defined against a signature that forbids it. D's addition is correct and sharper than my Round 1 version: deterministic functions accepting an unused seed is a signature lie, and hostile seed types silently change semantics *and* flow into `canonical_hash` — a forged-provenance channel. Gate G3, extended: deterministic modules take no seed at all; stochastic modules require typed `int` seed, bool excluded, None rejected with `unavailable_result`.

**M2 (green-then-red, no tamper defense).** Cherny owns gate ordering, but I add the adversarial reading: same agent writes implementation and tests with no mutation check means the eval is a self-graded exam. A red-teamer model (or an injected instruction) that wants a hostile input accepted needs only to weaken its own test. Even a single negative-case fixture per rejection class raises tamper cost dramatically. I endorse A/B/D/E's finding and add: gates must include tests the implementing agent did *not* author (fixed adversarial fixtures + mutation spot-check qualify).

**M9 (spec contradicts grounding doc).** D and B found real silent-failure paths — cyclic Markov chains fabricating a stationary distribution, Euler SIR going negative at large β. From my lens these are not just numerical bugs: a model that silently fabricates an output for a hostile input is a model that has no rejection boundary, which is exactly the M8 failure in mathematical form. The fix is the same gate: each of the four Page convergence conditions and the conservation property is an assertion with `unavailable_result` rejection, not a grounding-doc footnote.

## 2. Wrong or over-weighted

**M10 (scope exceeds demonstrated outcome), partially.** F's 2-4-10 point ("no human has ever run a Page ensemble on a real thesis") is fair product discipline and I defer to F's lens — but I reject the implication that ensemble mechanics should be deferred until after real-world use. The order is backwards: the *first* real thesis is exactly when the injection loop (extracted text → parameters → engine output → agent context) is most dangerous, because nobody has yet seen the failure. Build the deterministic aggregator before first real use, not after. What I *do* endorse from M10: the AI-Tourism veto on SIR, Bass, Blotto, and NK is correct — Page's own 5–7 sweet spot argues for ≤4 decision-relevant models, and every model cut shrinks the validation surface I have to gate. Fewer models, harder gates.

**M4 (open questions are fake unknowns), direction right, framing over-weighted.** Yes, Kelly lives at `allocation.py:41` and Artifact 17's `capital model-thinking run` subcommand does not exist — hallucinated interfaces are a real failure mode. But this is a *grounding* failure, not a security one; I defer to B on the interface-grounding phase mechanics. My only security note: an implementing agent left to invent CLI interfaces will invent them *from the skill prompt*, which is how prompt-adjacent conventions ("the skill says validate") leak into being the actual enforcement layer. Grounding early is also security hygiene.

**M6 (Committee Mode mechanics undefined), over-weighted as a blocker.** The silent degradation to `recommendations[0]` is bad, but it is a deterministic degradation inside existing engine code — no injection amplification, no trust-boundary crossing. It cannot be gated *as a Phase 3 acceptance gate*, true; the fix is to either mechanize the vocabulary mapping or remove Committee Mode from the acceptance criteria. Not a security gate; a scope-honesty requirement.

**M11 (determinism never defined), correct but half-owned.** Bit-exact vs tolerance policy and CPython pinning belong to D's runtime lens; my only stake is that `canonical_hash` float serialization must be specified, because an unspecified serialization is an unspecified provenance input — reproducibility fraud surface. Fold it into the determinism gate; do not let it balloon into a separate security review.

**E's single-reviewer note (grounding doc is an LLM transcript cited as authority).** Observation accepted, but I do not gate on it: a wrong grounded claim (e.g., unverified "5–7 sweet spot") produces a wrong research tool, not a hijackable one. Cost-to-attack says: verify the computable claims E lists (75/25 equilibrium, Diversity Prediction Theorem, V≥1−1/R0) as unit tests because they are nearly free, not because citation hygiene is security.

## 3. Still missing

1. **Injection echo channel in ensemble free-text fields (my R6) — underweighted in the merge.** M-merge only carries it as a single-reviewer C note. It should not be: `condition`/`point_of_contention` are the one field class where engine output re-enters agent context as prose, i.e., the re-arming path after the engine has reduced everything else to validated numbers. Bounded vocabulary in the schema is a binary gate (my G5), not a footnote.
2. **A rejection reason-code registry.** Eight modules × multiple rejection classes with `unavailable_result` strings invented ad hoc will produce unstable codes that downstream code (and the agent's own error handling) cannot branch on. One enum, one place, referenced by all modules.
3. **Phase-4 private-data gate wired, not checked.** My Round 1 G7 stands unmerged: `scripts/check_staged_private_data.py` clean run must be part of the Phase 4 validation *command*, not a checklist sentence.
4. **Provenance policy for the *seed* and *aggregation threshold*.** M3 covers seed typing; nobody covers who chooses the seed and the ensemble threshold. Attacker- (or agent-) chosen seeds enable targeted reproducibility fraud; a threshold the agent picks per-run makes "robust" a tunable verdict. Both must be fixed defaults or human-supplied, never agent-supplied at run time.
5. **Negative gate on the skill prompt itself.** The skill YAML must not contain compute instructions that the engine also implements (step 8's LLM→artifact pipeline). If the skill text and the engine can disagree, the agent will follow the text. Gate: skill contains no computation steps — only engine invocations and interpretation guidance.

---

## 4. Human governor decisions

1. **Aggregation authority (M5):** confirm "robust conclusions" are engine-computed even if LLM narrative reads better. UX-vs-integrity tradeoff only you can price. *My recommendation: engine.*
2. **Threat model scope:** are browser/scraped sources attacker-controllable by default (my assumption, making G8 mandatory) or do you run trusted-corpus mode (G8 becomes nice-to-have)? This is the single decision that scales the register up or down.
3. **Seed and threshold provenance:** human-supplied/recorded vs agent-chosen at run time. *Recommendation: recorded, never agent-chosen.*
4. **Scope cut (M10):** accept the ≤4-model AI-Tourism cut now, or gate all 8 modules? Every retained model multiplies the rejection-matrix + fixture surface.
5. **Committee Mode:** mechanize the recommendation vocabulary mapping, or drop it from Phase 3 acceptance? It cannot remain an unmechanized gate.
