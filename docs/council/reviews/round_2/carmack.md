## 1. Strongest findings — MUST be enforced as gates

**M5 (ensemble has no computation site) — the single most important finding in the packet.**
Step 8 of the skill being a direct LLM→final-artifact pipeline means the flagship deliverable is freehand-generated by the same agent that read the inputs. Everything else in the plan (pure functions, unavailable_result, canonical_hash) is worth nothing if the final artifact is prose. The fix is exactly my shape: a deterministic compiler over an Ensemble IR — schema-validates atoms in, verdict out, no LLM in the loop. **Gate: build of `ensemble-result.v1` instances happens only in a pure module; a test feeds atoms and asserts byte-identical output; the skill text may reference the module but never narrate results into the artifact.**

**M3 (seed=None contradicts repo convention; lying seed signatures).**
This is my R1 finding arriving with consensus weight. A seed parameter no RNG consumes is a lie in the signature, and C4 ("every number reproducible from inputs+seed") is untestable while the default is `None`. **Gate: every stochastic function has a required keyword-only `seed: int`; every deterministic function has NO seed parameter; grep for `seed=None` in new modules → FAIL.**

**M8 (validation is prose, not tests) + M7 (no adversarial fixtures).**
`fixtures/adversarial/` already exists with 10 fixtures — the convention is sitting there and the plan ignores it. Capping dimensions "in documentation" is control-by-doc, i.e., nothing. Asserts on entry are free. **Gate: each of the 8 modules ships ≥2 adversarial fixtures (one non-finite/bool-typed input, one over-cap dimension) that assert `unavailable_result` or rejection; the assert/limit table from R1 is enumerated in the plan, not improvised.**

**M1 (wrong schema target) — cheap, blocking, must be fixed first.**
Conformance against a schema whose required fields model outputs structurally cannot have means every atom fails validation on day one. And the real atom shape is already in the repo (`$defs.atom`). **Gate: Artifact 1.5 (`atoms.py` + correct schema ref) exists before any model module; `validate_evidence_atom` passes on every atom. `input_trust_class` in the provenance enum: yes — it's one enum value that makes Carlini's injection finding (C) representable in data instead of prose. Enforce both.**

**M4 (fake open questions) — resolve by probe, before Phase 2.**
`allocation.py:41`, `plugin/commands.py`, `methods/packs.py` are one grep away. Leaving them open guarantees interface hallucination, and Artifact 17 hard-codes a subcommand that does not exist. **Gate: no artifact may list as "open" anything answerable by a repo probe; CLI name resolved before skill text is written (my G-J12).**

**M2 (green-then-red; no eval-tamper defense).**
Same agent writing implementation and tests is self-grading. `tests/mutation/` exists — mutation killing is the mechanical answer to "are the tests real." **Gate: each phase artifact lists a failing-test-first step; per-model ≥1 sign-flip and ≥1 off-by-one mutation killed (my G-J13). Binary: mutation survives → test suite is a smoke test → FAIL.**

**M9 (spec contradictions vs grounding doc).**
Markov convergence conditions, SIR discrete-difference vs. Euler, Polya multi-trial, bandit algorithm names — these are contradictions between the spec and its own authority document. My R1 gates G-J3/G-J6/G-J10/G-J8 cover the mechanics; the register enforces them. One addition: the Markov matrix convention (Page vs. row-stochastic) must be stated in the docstring AND tested with a transposed-matrix fixture, or the agent/engine will disagree silently on a plausible wrong answer.

**M11 (determinism never defined).** Bit-exact vs. tolerance policy, CPython pin, canonical float serialization — my G-J2 verbatim. Enforce.

## 2. Wrong or over-weighted

- **M6 (Committee Mode) — real but over-weighted as a Phase 3 *gate*.** The six-string vocabulary silently degrading to `recommendations[0]` is a genuine train wreck, but the fix is a one-line input validation (unknown string → `unavailable_result`), not a blocked phase. Enforce as a module-level assert, not a phase blocker. If Committee Mode's mechanics can't be specified in a page, cut it — it's not the value path.
- **M10's "8 reference files threaten byte-exact cache prefix" — over-weighted.** Cache-prefix economics are a real cost, but the answer is fewer reference files (Page's own 5–7 sweet spot argues ≤4 models), not cache engineering. The scope criticism (no customer outcome, no end-to-end smoke) is the sharp half of M10; the token-budget half is secondary.
- **E's "grounding doc is an LLM transcript cited as authority" — directionally right, wrong remedy.** Don't demand primary sources for the 5–7 sweet spot; demand the *computable* claims (75/25, V ≥ 1−1/R0) become test fixtures, which costs an afternoon. If the transcript is wrong about a testable number, the test catches it. That's the compiler move; source-archaeology is not.
- **A's 12 named gates (G-SCHEMA-1…G-TOKEN-1) — right instinct, but token-efficiency of error messages is not a build gate.** Gate it as a lint-style check if cheap; don't let it rank above M5/M3/M8.
- **B's "phase 2 should split for parallel worktrees" — process optimization, not correctness.** Cherny's domain; I don't gate on it.

## 3. Still missing (nobody said it)

1. **A shared atom constructor is now half-said (my R1 atoms.py, M1's schema fix) but nobody requires `additionalProperties: false` on the *per-model* atom schemas.** Schema-validated atoms are the closest thing to a compiler this repo has; without closed schemas, the 8 modules drift in 8 directions and canonical_hash becomes theater. Gate it.
2. **Performance budget.** My G-J14: single ensemble run ≤ 5 s at default caps, enforced by a timing test. Nobody in the packet measured anything. Back-of-envelope says the caps make it fine — but "fine" must be a test, not an expectation.
3. **Correlated-models field in the ensemble schema** (my R1 missing spec #7, grounded in Section 9 of the doc). Without it, the Diversity Prediction Theorem's failure mode (a) is unrepresentable — the ensemble can certify diversity it doesn't have.
4. **RNG consumption order per stochastic model.** Three reviewers touched determinism; none specified the *order* draws are consumed (placement→scan→vacancy; bit→dependent-bit→table; per-trial child-seed derivation). Two correct implementations with different orders are both "deterministic" and mutually incompatible. One table in the plan fixes it.
5. **The full existing test suite should gate every phase, not Phase 4** (B found the symptom; the fix is: run the suite as a gate at every phase boundary — cheap, mechanical).

## 4. Human governor decisions

1. **Determinism class:** bit-exact across CPython versions, or within-version only? Decides how much G-J2 costs. (My default: within-version exact + pinned runtime note.)
2. **SIR honesty policy:** `unavailable` on unstable Euler, auto-substepping (Δt=1/k, ~20 lines, my recommendation), or RK4?
3. **Markov convention:** Page's row/column convention vs. standard row-stochastic. One must win; both cannot coexist.
4. **Scope cut:** Do you accept ≤4 decision-relevant models in Phase 1–2 (Page's own sweet spot, kills the cache-prefix risk and the AI-tourism veto) with the rest deferred? This is a product decision I won't make for you — but the current 8-model plan has never delivered one end-to-end moment of value (F's 2-4-10 point stands).
5. **Blotto scope:** pairwise payoff (pure, cheap) vs. full enumeration (infeasible) — the provenance label flips on your answer.
6. **Committee Mode:** specify the mechanics in a page or cut it from Phase 3 acceptance. A gate on an unmechanized claim is a lie with a checkbox.
